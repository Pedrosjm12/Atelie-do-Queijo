## Prova de que os testes novos falham quando o item quebra

Feita localmente e desfeita (`git checkout`):

- `--ouro: #c9a24b` → `#c9a24c` em `app/globals.css`: falha "globals.css define --ouro com o valor exato da spec".
- `a{color:#fff}` acrescentado a `components/Logo.module.css`: falha "nenhum CSS Module nem o CSS global usa cor literal fora dos tokens" (`components\Logo.module.css:65 -> #fff`).
- `font-weight` do grupo `h1, h2, … .preco-grande` de 500 para 400 em `globals.css` (com rebuild): falha "cada papel tipográfico usa a família e o peso da tabela da §3.2".

## Achados para decisão do dono

Estado atual de cada um: [aceite.md, seção 2.4](aceite.md#24-desvios-aguardando-decisão-do-dono).

- **Cores em TSX fora de SVG:** `app/opengraph-image.tsx` usa `#14110F` e `#C9A24B` literais (iguais aos tokens `--cave` e `--ouro`). É imagem gerada, não CSS, e o teste de cores não a varre. Aceitável, mas se o token mudar a imagem não acompanha.
- **`color-mix` em três regras** (`CheeseViewer.module.css`, `QuantityStepper.module.css`) mistura `--creme` e `--pedra-clara` com `transparent` a 65% para o estado desabilitado. Deriva de token, o teste permite, mas a spec não prevê essas cores intermediárias.
- **Contagem "9 seções":** resolvida. São a §5.2 a §5.10 (a faixa de aviso é a §5.1). Ver item 3.
